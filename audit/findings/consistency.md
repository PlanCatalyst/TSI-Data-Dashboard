# Consistency audit

Run `20261015T001106Z`. Generated by `audit/derive_consistency.py`. Accounting table: `audit/results/consistency_accounting.csv`.

## Headline

No unexplained drops: every row lost between stages is attributed to a counted reason, and the independent replica of cleaning and dimension selection reproduces the on-disk row counts.

**agoda (DC_TOF_AGRL) GDP join leak.** 189 of 3602 non-null harmonised rows have no NY.GDP.MKTP.CD > 0 for the same country-year. `_apply_agoda_gdp_normalization` only converts rows where the join succeeds (`work.loc[agoda_mask, 'value'] = agoda['value'].values` writes the unchanged USD-millions value back for the rest). Those rows are then scored by `GoalRatioScorer(goal=0.02)` as if the number were an ag-flow/GDP ratio, so need saturates at 100 and the dashboard shows 0.0.
Direction: ratio far above the 0.02 goal gives need 0, which the publish boundary shows as 100 (best). Of the affected rows that fall on a published country-year, 0 are published as 100.0, 0 as another value, 60 as null. A missing GDP therefore turns a data gap into a top score. Fix: set value to NaN where GDP is missing (or drop the row) instead of keeping the USD-millions value.
